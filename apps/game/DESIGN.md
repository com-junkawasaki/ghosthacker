# Ghost Hacker 全体設計

## 0. ハイレベルコンセプト

* 舞台：**2068 年 Tokyo（海面上昇により水路とスカイブリッジが共存する“水の都”。フォトニクス通信が街全体を覆い、混乱や暴力の少ない、空気感の軽い平和的なSF世界）
* プレイヤーの支援者：**Tamaki（タマキ） — 女性の医師。博識で、柔らかく可愛い雰囲気。フォトニクス通信や次世代医療システムにも通じ、SF 技術を自然に語れる“未来の専門家”。話し方は親しみやすく、平和的な世界観に調和する落ち着いた空気感を持つ。

  * 役割：ナビゲーター兼、Ghost Hacker プロジェクトの専任サポート。
  * 性格：冷静・博識・時々ブラックユーモア。AI と人間の心理両方に詳しい。
* タイトル（確定）：**Ghost Hacker**
* コアメッセージ：**「影をハックすると、人は変わる。」**
* 構造は既存の因果パズル & ゴースト生成フローをそのまま利用しつつ、世界観を 2068 年 Tokyo に統合。
* タイトル（仮）：**Ghost Schema / ゴースト・スキーマ**
* コアメッセージ：**「人のふり見て我がふり直せ」——自分の“影”であるゴーストを観察・修正することで、自分自身の認知や価値観を見つめ直す。**
* テーマ：嘘・矛盾・断片記憶・因果関係・感情の取り違え。
* トーン：リベラルアーツ × サイコロジー × サイバーゴシック。
* プレイ感：1セッション 3〜7 分程度の“思考パズル＋対話アドベンチャー”。

## 1. プレイヤーファンタジー（体験の核）

* プレイヤーは「自分の影であるゴースト」を生成し、そのゴーストの **歪んだ因果関係と感情ラベル** を観察・修正していく。
* ゴーストは LLM によって駆動され、嘘・矛盾・断片的記憶を含んだ語りを行う。
* プレイヤーはパズル操作＆簡単な対話によって、ゴーストの内部スキーマ（認知構造）を書き換え、最終的にゴーストを“成仏”させる。

---

## 2. コアゲームループ（1セッション ≒ 5分）

1. **ゴーストの悩みが提示される**

   * ゴーストが短いモノローグで「最近ずっと引っかかっている出来事」を語る。
   * 嘘・矛盾・因果のねじれ・感情の取り違えが混ざっている。

2. **断片ログの確認**

   * 下部のカード（イベント断片）をスワイプで確認。
   * 必要であれば、音声／チャットでゴーストに質問 → 新しい断片が生成される。

3. **因果パズルフェーズ**

   * 時系列モード：ドラッグでイベントの順序を並び替える。
   * 因果モード：イベント間を線で結び、因果関係を修正する。
   * 感情モード：感情アイコンをドラッグし、適切な感情ラベルを割り当てる。

4. **ゴーストの再推論（リプレイ）**

   * 3D 因果グラフが再構成されるアニメーション。
   * ゴーストが“気づき”のモノローグを話す（整合したストーリーテリング）。

5. **リフレクション & 進行**

   * 「自分にも思い当たる点はある？」等の簡易な問いに回答。
   * セッションごとに「学びメモ」「ゴーストの安定度」が蓄積される。

## 3. システム構造（概略）

### 3.1 ゴースト内部モデル（状態パラメータ）

Rust 側で管理する Ghost の状態例：

* `truth`（真実性）
* `coherence`（一貫性）
* `memory_integrity`（記憶の整合性）
* `noise`（認知ノイズ）
* `emotion_distortion`（感情歪み）

これらは、

* プレイヤーの因果パズル操作
* LLM の出力
  に応じて更新される。一定の閾値まで安定すると「成仏フェーズ」に入る。

### 3.2 LLM レイヤ

* 入力：

  * ゴーストの現在状態（上記パラメータ）
  * 直近のイベント断片
  * プレイヤーが構築した因果グラフ、感情ラベル
  * プレイヤーからの質問（テキストまたは音声→テキスト）
* 出力：

  * ゴーストのセリフ（断片的記憶・矛盾を含む）
  * 追加のイベント断片
  * 成仏時のモノローグ

### 3.3 表現レイヤ（Rust + Bevy 想定）

* 2D UI：

  * カードリスト、ボタン、モード切り替えタブ
* 3D 表現：

  * 因果グラフ（ノード＆エッジ）
  * ゴーストのアバター
  * 再構成時のアニメーション（ノードの収束・光の安定など）

## 7. ゴースト生成フェーズ UI デザイン

### 7.1 目的

* 「自分のゴースト」を短時間・ライトな操作で生成する。
* 生成された情報は TerminusDB（RDF グラフ）に格納され、
  ゴーストの初期スキーマ（認知スタイル・感情傾向・価値観の重み付け）として LLM（Hume）に渡される。

### 7.2 フロー概要（スマホ縦画面）

1. **イントロ画面**

   * ゴーストのシルエットと短いテキスト。
   * 「これは、あなたの影から生まれるゴーストです。」
   * [はじめる] ボタンのみ。

2. **クイック性格／認知スタイル診断（カード選択）**

   * 1画面に 3〜4 枚のカードを表示し、スワイプ or タップで選択：

     * 「時間に厳しい / ざっくり / 気にしない」
     * 「他人の評価がとても気になる / 少し気になる / あまり気にしない」
     * 「感情的になりやすい / 論理的に考えがち」など。
   * 選択は RDF 上で `:ghostX :hasTrait :HighSocialSensitivity` のようにトリプル化。

3. **価値観ワードのタグ選択**

   * 「自由」「秩序」「効率」「美しさ」「公平」「混沌」などのタグをチップ UI で表示。
   * 最大 3 つまで選択。
   * RDF では `:ghostX :values [ :freedom 0.8, :order 0.2, ... ]` のように重み付きで保存（実装上は別ノードで表現）。

4. **感情反応スタイル（スライダー）**

   * 縦方向に 3〜4 本のスライダー：

     * 「不安になりやすい ←→ 落ち着きやすい」
     * 「怒りやすい ←→ 我慢しがち」
     * 「自分を責めがち ←→ 人のせいにしがち」 など。
   * 各スライダーの値は初期の `emotion_distortion` や `noise` の重みに反映。

5. **初期ゴーストプレビュー**

   * 3D or 2D アバターが、その設定に応じた色・揺れ方・明滅パターンで表示。
   * 横に “要約テキスト”：「評価をとても気にする、少し衝動的なゴースト」など。
   * [このゴーストで始める] / [もう一度やり直す] ボタン。

### 7.3 TerminusDB / RDF モデル（概略）

* `:Ghost` クラス：

  * `:hasTrait` （例：`:HighSocialSensitivity`, `:Impulsive`）
  * `:hasValuePreference` （中間ノードで値と重み）
  * `:hasCognitiveStyle` （例：`:Analytical`, `:Emotional`）
  * `:hasInitialState` （後述の数理モデルの初期値を保持するノード）
* UI の各入力は RDF トリプルとして TerminusDB に保存され、
  起動時にクエリして LLM プロンプトのコンテキストを構築する。

## 8. ゴースト内部パラメータの数理モデル（更新ルール）

### 8.1 パラメータ定義

各パラメータは [0, 1] の連続値とする：

* `truth`：

  * ゴーストが「事実に沿って語れている度合い」。
* `coherence`：

  * 語りの一貫性（自己矛盾の少なさ）。
* `memory_integrity`：

  * 時系列や因果構造が安定している度合い。
* `noise`：

  * 語りに含まれるランダム要素・飛躍・錯覚の強さ。
* `emotion_distortion`：

  * 実際の状況と感情ラベルのズレの大きさ。

### 8.2 更新の基本形

プレイヤーの行動ごとに、以下のような更新ルールを適用する（例）：

1. **時系列を正しく並び替えた場合**

   * 修正されたイベント数を `k_time`、全イベント数を `N` として：
   * `Δmemory_integrity = α_t * (k_time / N) * (1 - memory_integrity)`
   * `Δnoise = -β_t * (k_time / N) * noise`

2. **因果関係を正しく結び直した場合**

   * 正しい因果リンク数を `k_cause`、総リンク候補数を `M` として：
   * `Δcoherence = α_c * (k_cause / M) * (1 - coherence)`
   * `Δtruth = γ_c * (k_cause / M) * (1 - truth)`
   * `Δnoise = -β_c * (k_cause / M) * noise`

3. **感情ラベルを正しく修正した場合**

   * 修正された感情タグ数を `k_em`、対象イベント数を `L` として：
   * `Δemotion_distortion = -α_e * (k_em / L) * emotion_distortion`
   * `Δcoherence = γ_e * (k_em / L) * (1 - coherence)`

4. **ゴーストの語りが新たな矛盾を含んでいた場合**

   * 外部の一貫性チェッカー or ルールベースで矛盾度合い `m_incoh` ∈ [0, 1] を算出：
   * `Δcoherence = -δ_c * m_incoh * coherence`
   * `Δnoise = +δ_n * m_incoh * (1 - noise)`

5. **セッション終了時の緩和項（自然安定化）**

   * セッションごとに小さな収束項を加える：
   * `memory_integrity ← memory_integrity + λ_m * (target_m - memory_integrity)`
   * `noise ← noise + λ_n * (target_n - noise)`
   * ここで `target_*` はゴーストの「性格」に応じて異なる平衡点（生成フェーズから計算）。

### 8.3 TerminusDB / RDF との連携

* 各セッション終了時に、Ghost の状態ノードを更新：

  * `:ghostX :hasState [ :truth 0.72 ; :coherence 0.65 ; ... ]` のように格納。
* 過去の状態推移も別ノードとして履歴管理し、

  * 「このゴーストはどう変化してきたか」をメタ的に可視化することも可能。

## 9. LLM（Hume）に“意図的な矛盾”を出させるプロンプト設計案

### 9.1 基本方針

* 矛盾や断片化は **完全に LLM 内部に任せるのではなく**、
  オーケストレーション層と RDF グラフの操作で制御する。
* Hume LLM には以下を渡す：

  1. ゴーストの現在状態（truth, coherence, noise, emotion_distortion など）。
  2. 関連する RDF トリプルから抽出した「世界の断片情報」。
  3. 現在のシーン（テーマ）とプレイヤー発話。

### 9.2 システムプロンプトの構造（擬似例）

* 役割指定：

  * 「あなたは『Ghost』というキャラクターです。ユーザーの“影”として振る舞います。」
* ステート指定：

  * JSON 風に状態を渡す：

  ```json
  {
    "truth": 0.4,
    "coherence": 0.3,
    "memory_integrity": 0.2,
    "noise": 0.8,
    "emotion_distortion": 0.7,
    "traits": ["HighSocialSensitivity", "Impulsive"],
    "values": {"freedom": 0.8, "order": 0.2}
  }
  ```
* 振る舞いルール：

  * `coherence` や `noise` の値に応じて、

    * 記憶の抜け
    * 時系列の混乱
    * 自己矛盾
    * 感情の過大・過小評価
      を表現するよう指示。

例：

* `noise` が高いとき：

  * 「時々、さっき話したことと少し矛盾しても構いません。」
  * 「因果関係を取り違えるような語り方をしてもいいです。」
* `coherence` が上がるにつれて：

  * 「前に話した内容と整合するように、ゆっくりと矛盾を減らしてください。」

### 9.3 オーケストレーション側での“矛盾注入”テクニック

* RDF グラフから **あえて一部のトリプルを抜いた状態**でコンテキストを渡す：

  * → LLM は “知らない部分” を補完しようとし、そこにズレが生じる。
* 過去発話の一部を意図的にサマライズし、

  * 細部を欠落させたメモリとして渡すことで、断片感を演出。
* noise が高いときは：

  * 「重要な事実」を抜いた RDF コンテキストを渡す
  * 「焦点がズレた事実」を強調して渡す

### 9.4 Hume の感情情報の利用

* Hume 側から得られるユーザーの感情推定（音声・テキスト）を、

  * ゴーストの反応スタイル制御に使う：

    * ユーザーが不安そう → ゴーストがやや共感的に
    * ユーザーが楽しそう → ゴーストが軽い皮肉・ジョークを混ぜる など。
* プロンプト上では：

  ```json
  {
    "user_emotion": "anxious",
    "user_valence": -0.4,
    "user_arousal": 0.7
  }
  ```

  のようなメタ情報を付与し、
  「ユーザーの感情状態を踏まえて、過度に追い詰めないように語ってください。」
  といった安全・体験品質の指示も同時に与える。

## 10. 公式ゴースト 8 体のストーリー案

### 1. Ghost A：**断片飛躍型（Fragment Jumper）**

* **歪みタイプ**：memory_integrity が極端に低い。記憶が飛び飛びで、重要な部分が抜け落ちる。
* **世界観内ストーリー**：

  * 2068 Tokyo の水辺で働く配送ドローン整備士の“影”。
  * 仕事中の重大な事故を“覚えていない”。
  * 時系列カードが 5 枚中 3 枚欠落しており、因果が繋がらない。
* **因果パズルの特徴**：

  * メインは時系列復元。
  * Tamaki が「この子、どうしても“大事な瞬間”を語らないの…」とサポート。

### 2. Ghost B：**感情反転型（Emotion Inverter）**

* **歪みタイプ**：emotion_distortion が高い。喜びの場面で“怒り”をつけたり、その逆も。
* **ストーリー**：

  * 元は水上アートのインストラクターの“影”。
  * 自分の作品を褒められると“怒り”の感情が付いてしまう謎。
* **因果パズル**：

  * 感情アイコンの付け替え中心。
  * プレイヤーは「なぜこの場面に怒り？」を解き明かす。

### 3. Ghost C：**因果循環型（Loop Thinker）**

* **歪み**：coherence が極端に低く、因果関係がループ状（A→B→C→A）。
* **ストーリー**：

  * 水路沿いの研究都市で働くエンジニアの“影”。
  * 「失敗したのは成功したせいで…」など自己矛盾のループが止まらない。
* **パズル**：

  * 因果矢印を切り離し、正しい方向に付け直す。

### 4. Ghost D：**嘘と自己誤認型（Self-Misleader）**

* **歪み**：truth が低く、本人も嘘か本当かわかっていないタイプ。
* **ストーリー**：

  * 水上医療ボランティアに所属していた人物の“影”。
  * 人を助けたと語るが、RDF の断片では“助けられていた”側という矛盾。
* **パズル**：

  * 因果と感情の混合問題。
  * Tamaki「うん、これは“嘘”というより“真実の勘違い”だね。」

### 5. Ghost E：**価値観偏重型（Value Dominator）**

* **歪み**：value_model の偏りが極端。自由 or 秩序などが 0.95 など一点集中。
* **ストーリー**：

  * 浮遊式学校の講師の“影”。
  * “自由”を追求するあまり、すべての因果を「自由のため」に解釈してしまう。
* **パズル**：

  * 感情 + 因果のハイブリッド。
  * 価値観の変更がクリア条件。

### 6. Ghost F：**外部依存型（Other-Echo）**

* **歪み**：他者評価への敏感さが高すぎる。感情と因果が “誰が見ているか”で変化。
* **ストーリー**：

  * 水上舞台スタッフの“影”。
  * “誰に見られたか”で同じ出来事の記憶が全く変わる。
* **パズル**：

  * 同じイベントが複数視点で出る。どれが本人視点かを整理。

### 7. Ghost G：**妄想補完型（Fiction Patcher）**

* **歪み**：noise が高く、記憶の穴を“創作”で埋めてしまう。
* **ストーリー**：

  * 水の都の AI カフェで働いていた人の“影”。
  * 隙間に「ドラマチックすぎる」イベントが挿入される。
* **パズル**：

  * 創作イベントを見抜いて除外。

### 8. Ghost H：**沈黙型（Quiet Kernel）**

* **歪み**：発話量が極端に少なく、情報断片が必要最低限。
* **ストーリー**：

  * フォトニクス通信の技術者の“影”。
  * 自分の感情を“光の色”のようにしか語らない。
* **パズル**：

  * 少ない断片を正しく組み合わせて推論する“推測型”。
  * Tamaki「この子は“言葉じゃなくて色”で考えてるみたい。」

## 2. 主要フェーズ構成

### ● フェーズ1：問題提示フェーズ

* ゴーストの断片発話が上部に表示。
* 下部に断片カード（横スクロール）が並ぶ。
* プレイヤーは発話を確認し、次の因果パズルへ進む。

### ● フェーズ2：因果パズルフェーズ

3つのモードで構成：

* **時系列モード**：イベントカードをドラッグで並べ替え。
* **因果モード**：イベント同士を線で結び、因果関係を修正。
* **感情モード**：感情アイコンをイベントへドラッグし、適切な感情ラベルを付与。

### ● フェーズ3：再構成・気づきフェーズ

* 整理結果に基づきゴースト内部の因果グラフが 3D アニメーションで再構成される。
* ゴーストが“気づき”を語るモノローグを提示。
* プレイヤーは簡易な問い（リフレクション）に回答可能。

## 3. UI レイアウト案

### ● 縦画面（因果パズル中）

* 上：ゴーストのコメント領域。
* 中央：タイムライン or 因果グラフの編集エリア。
* 下：感情アイコン、イベント詳細、確定ボタン。
* 右下：音声/チャット入力ボタン。

## 4. インタラクション

* **ドラッグ＆ドロップ**：順序変更、アイコン配置。
* **タップ**：ノード選択、詳細表示。
* **フリック**：矛盾指摘や補助操作に対応可能。
* **音声/チャット**：ゴーストへの質問、断片生成のトリガー。

## 5. ゴーストのリアクション

* 時系列の矛盾や因果不成立に反応する短いコメントを表示。
* 感情タグがズレた場合に違和感を示す。
* クリア時には整合的な認知フレームへ収束したコメントを返す。

## 6. 学び（リベラルアーツ要素）

* 認知バイアス、因果誤認、感情解釈、哲学的テーマの自然習得。
* 「解説」ボタンで簡易メモを閲覧可能。
